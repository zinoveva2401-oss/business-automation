# DOKRUTI visual, product and browser QA contract

## Pre-production gate

Confirm current source versions/status and actual contents for Drive `Референсы` (view relevant files), live Radar `11_КОНКУРЕНТЫ_И_РЕФЕРЕНСЫ`, `02_Бренд-система`, `03_Активы_проекта`, `12_САЙТ_МАТРИЦА`, relevant content/channel/technical registers, and real repository state. Record missing or limited source access.

Before code, create the whole-page `CURRENT → TARGET → ACTUAL` transformation, distinct user job/value/action per section, selected and rejected current donors, specific DOKRUTI adaptations, visual-hook / Remove-Text result, adaptive trend-fit result, truthful asset decisions, interaction plan, visitor conversion path, and acceptance evidence. Run executable SPEC-LINT for significant work.

Before code, also create a concept-divergence record with at least three materially different concepts, scores from 1–5 for hook / brand / conversion / interaction / freshness, and an internal selection rationale. Record prohibited patterns from the latest rejected Home before production. Define a measurable section-height budget for desktop and mobile plus a total scroll-height target; ordinary blocks above 0.8 viewport need a written user/value reason. Name distinct visual peaks and cap `giant serif headline + large empty space + right-side panel` at one occurrence. Plan sticky navigation after the hero, persistent primary action, return-to-top and mobile thumb-reachable action where required.

## Required whole-page visual evidence

For the exact final SHA or live local artifact, capture sequential actual viewport renders across the complete page at desktop 1440 CSS px and mobile 390 CSS px. Scroll in viewport-sized segments and include all sections; a stitched full-page screenshot is not sole evidence. Check the real browser viewport and link each capture to exact route and artifact SHA. Include the reference artifacts/URLs used and their actual fit. Test material interactions at browser widths.

### Owner-facing screenshot handoff

Visual evidence handoff is incomplete until every required screenshot file exists and the screenshots are actually attached or displayed inline in the owner-facing chat. For every capture, identify its section, viewport, local file path, exact source artifact SHA, and (when useful) file checksum. Before handoff, verify the listed captures against the files and confirm the images are visibly surfaced in that conversation. Never claim “evidence available in chat” (or equivalent) unless the screenshot images are actually shown or attached there; a path, report, or screenshot inventory alone does not satisfy this requirement.

### Reference delta and public-status leak gate

If the owner has not frozen a single exact reference, do not require an `APPROVED REFERENCE + SHA`. Use `CURRENT VERIFIED DONOR SET → concrete principles/mechanics → AFTER render comparison`, naming verified donors, mechanisms, and the observed result. If the owner did freeze one exact reference, compare to that reference and its specified SHA. Inspect the actual rendered public interface and fail on any internal setup, audit, production, QA, readiness, or workflow status, even if the content source or build check passes.

## Experience, content and conversion

Check all of these against live source data and actual rendered behavior:

- instant brand/user understanding and a memorable visual hook before long text;
- complete page path with pace, density, transitions, narrative continuity and cumulative trust;
- every block has a distinct user job, new value and next action; no duplicated article/current-items module;
- every pain option is a direct one-click link to a useful destination;
- article hierarchy is exactly one featured + three supporting current published articles where available, updates with source data, and does not duplicate the same set elsewhere;
- actual tools/products, actual active services with situation-to-destination language, founder/approach and trust facts;
- founder image is checked for reality, identity, provenance, approval and rights; AI/composited art is never described as documentary photography;
- every displayed channel has verified link, status, role and user reason; empty/inactive/unready channels are not presented as active, and omitted existing sources have an evidence-based rationale;
- at least the selected meaningful interaction moments, correct CTA reason/destination, event hooks, no unnecessary second click;
- public language has no internal proof/status/production jargon or invented promise/number.
- public UI exposes no internal setup, audit, production, QA, readiness or workflow status.
- observed total page height meets its predeclared target; each ordinary section stays within its budget or has an evidence-backed reason for exceeding it.

## Technical, access and responsive checks

Run as applicable: keyboard-only path, visible focus and semantics; reduced-motion behavior; contrast and touch targets; actual desktop/mobile layout and crops; horizontal overflow; image load/decode/alt; direct URL/deep-link behavior; local link and route checks; browser console and network errors; metadata/schema; analytics hooks; privacy/legal and security boundaries; measured media/performance; existing project check and production build. Distinguish observed PASS, FAIL and UNKNOWN. Build or DOM data alone is not visual proof.

## 25-lens final review

Review the exact final rendered page for: 1) first impression, 2) three-second hook, 3) brand clarity, 4) information architecture, 5) user jobs, 6) navigation, 7) click depth, 8) conversion, 9) trust, 10) founder credibility, 11) content usefulness, 12) article hierarchy, 13) product/tool clarity, 14) service clarity, 15) channels, 16) typography, 17) color, 18) density/whitespace, 19) interaction, 20) motion, 21) originality, 22) current signal fit, 23) mobile, 24) accessibility/performance, 25) portfolio/shareability/showcase quality. Also answer whether people want to keep scrolling, show it to someone else, and follow/contact/buy/use a useful next step.

When no exact owner-frozen reference exists, the required comparison is the current verified donor set, concrete extracted principles/mechanics, and their observable implementation in the after render. Do not block on an approved reference/SHA that the owner never froze.

## Review decision

Run relevant sequential read-only specialist passes on the exact final artifact, then Review Chair. Report `PASS / FAIL / UNKNOWN` with observed evidence, artifact truth, final SHA, viewport and defects. Product, visual or experience failure cannot be overridden by technical success. Repair material issues together and rerender; review the new artifact. Unknown material criteria block READY. Preserve scope and owner decisions. Never merge, deploy or publish unless explicitly authorized.
