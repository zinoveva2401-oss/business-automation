# DOKRUTI product production executor — autonomy overlay v1.1.0

For substantial product work, route first through the shared Core at `.agents/skills/ai-business-os/references/product-factory.md` and apply the versioned Product Factory local autonomy overlay in `products/AGENTS.md`. The shared Core owns strategy and product methods; the local overlay owns the preproduction definition of done, self-heal routing and handoff block. This patch does not change Business OS v2.0.11 RELEASE.

This Skill supplies execution routing and must not turn an incomplete internal stage into an owner handoff:

1. Restore the exact product/task source and inspect existing target files before editing. Mark unavailable sources precisely; request owner access only when that access is a real prerequisite.
2. Translate a business-level instruction into the overlay's complete applicable gate ledger, specialist route, evidence budget, stop condition and acceptance criteria. Do not ask the owner to dispatch routine work.
3. If a criterion is missing or fails but is correctable, route it to the responsible specialist, repair it, recheck it and continue. Never stop merely to ask whether normal research or repair should proceed.
4. For coded or interactive output, follow `docs/PRODUCT_EXECUTION.md` and the approved product design/technical source. Keep changes inside the exact product folder and preserve unrelated products.
5. Produce the requested artifact in its native format. Do not impose an ebook, PDF, spreadsheet, web app or other default.
6. Inspect the actual artifact and close all applicable research, commercial, legal/IP/claims, technical, visual/UX and independent review gates. Apply one consolidated correction pass, recheck corrected criteria and run regression review.
7. Before handoff, Architect/Supervisor checks `ARE ALL REQUIRED INTERNAL GATES CLOSED?`. If no, block owner handoff and route the open gates back internally. A representative prototype alone never passes this check.
8. Return one owner decision package only after internal gates close and only if a material owner decision remains. Never ask the owner to inspect unfinished QA, choose specialists/tools, or authorize ordinary repair.
9. Do not publish, sell, change permissions, incur material spend or write to an external source unless that action is explicitly authorized in the parent task.

The Product Factory project is scoped to `products/`. Do not create Site, Content, Automation or Client Factory projects here. Future `CLIENT_WORK` must use the shared Core's conditional isolation boundary and the client's authorized project/state; never mix client and DOKRUTI data, brand, files, credentials or access.
