# Knowledge Capital & Product Mining / превращать работу в интеллектуальные активы

## Purpose

Каждая сильная задача, которую DOKRUTI реально решил для себя, может стать повторно используемым капиталом. Business OS обязан замечать такие возможности без того, чтобы Светлана вручную придумывала продукты после каждого проекта.

## 1. Work-to-asset scan

После значимой VERIFIED работы проверь:
- повторится ли проблема у других владельцев/бизнесов;
- есть ли собственная методика/последовательность;
- есть ли before/after evidence;
- можно ли отделить reusable часть от приватного контекста;
- можно ли превратить результат в шаблон, чек-лист, калькулятор, Skill, книгу, интерактив, мини-продукт, услугу, кейс, обучение или лицензию;
- есть ли уже такой объект/гипотеза в каноническом банке.

## 2. Dedupe-first capitalization

Новая полезная находка **не равна новой продуктовой строке**.

Сначала:
`найти существующую продуктовую гипотезу/актив → обновить evidence/угол/формат → создать новый объект только если ценностное ядро и покупательский результат действительно самостоятельны`.

## 3. Capitalization Card

Для кандидата достаточно:
`проблема / кому / что мы уже сделали для себя / reusable method / доказательство / возможные носители / платная ценность / бесплатные substitutes / риск / ближайший дешёвый тест / куда записать`.

Не запускать производство автоматически. Карточка — мост в Product Opportunity Gate.

## 4. Examples for DOKRUTI

Примеры классов сигналов:
- настройка Business OS/Skills/контекста → продукт/книга/интерактив «как построить второй мозг бизнеса»;
- обучение Codex → технический playbook/diagnostic/product;
- premium site production → implementation service + case + reusable specification system;
- channel packaging → service/product/checklist;
- content factory → creator/business content operating system;
- analytics setup → implementation service + calculator/template.

Это примеры, а не утверждённые SKU.

## 5. Evidence flywheel

`решили для себя → сохранили метод → показали proof → превратили в контент → проверили спрос → Product Factory → продали → получили VOC → усилили метод`.

Один и тот же proof может усиливать сайт, контент, продукт и услугу, если права/приватность позволяют.

## 6. Knowledge base write-back

После доказанного метода записывай в минимально подходящее место:
- task/RUN learning;
- project playbook;
- asset register;
- product hypothesis bank;
- case/evidence register;
- Skill core — только после стабильности и regression.

Не создавать новый лист/папку без доказанного структурного gap.
