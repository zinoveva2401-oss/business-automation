# Growth / Distribution Loop v2.0.10 | r9 FINAL

## Purpose

Turn verified public/product assets into qualified audience movement, return behavior, product intent and measurable business outcomes. Growth does not replace Strategic Intelligence or Content Factory; it programs the channel around evidence.

North star is not raw follower count. A follower target may be a sprint objective, but the operating loop optimizes qualified discovery → useful consumption → follow/return → downstream action/revenue where the destination is ready.

Use the detailed [Growth Execution Operating System](growth-execution-operating-system.md) for target math, media programming, winner/loser loops, retention/reactivation, referral/community and subscription/CRO routes.

## 1. Channel job and baseline

For each active channel/experiment define one primary job:
`DISCOVERY / SEARCH / TRUST / COMMUNITY / CONSIDERATION / CONVERSION / RETENTION`.

Before advice read current account state and available analytics: profile/community readiness, audience, reach mix, top content, retention/read behavior, follows/unfollows, profile visits, repeat/return signals, clicks/messages/conversions and recent program mix.

No usable data → establish a baseline first. Do not invent “best time”, “best format” or algorithm rules from generic advice.

## 2. Target math

Translate a material target into the actual observable funnel supported by the platform:
`target outcome → qualified reach/discovery → entry/open → consume/retain → profile/channel visit → follow/subscribe → return → qualified next action → revenue when applicable`.

Own rates first; unknown rate = UNKNOWN + test. Do not reverse-engineer fake certainty from a round target such as 1000 followers.

## 3. Audience-platform fit

Check whether target audience and intent are realistically reachable, how discovery occurs and what next action is native. Weak/unknown fit receives a bounded experiment, not a permanent budget.

## 4. Profile / channel experience

The surface should explain who it is for, expected recurring value, what to consume first and the next step. Verify current brand/offer/links/messages/analytics. For material setup use [Channel Experience / Packaging](channel-experience-packaging.md).

## 5. Fresh platform intelligence

Use [Platform Intelligence / Operations](platform-intelligence-operations.md). Platform algorithms, formats, APIs and interfaces are dynamic. Check current official evidence, actual account analytics/interface and strong practitioner patterns only as hypotheses. Strategic Intelligence scouts global mechanics; Growth decides what is testable for DOKRUTI.

For video/short formats also use [Raw Footage / Edit Trend Bank](raw-footage-editing-trend-bank.md).

## 6. Growth hypothesis

Each experiment defines:
`segment / channel job / content-or-asset job / mechanic / baseline / primary metric / downstream metric / guardrail / success rule / horizon-or-sample logic / owner hours / cost / stop rule`.

Change one primary variable where practical. If many variables change, record low learning confidence.

## 7. Program portfolio, not random cadence

Maintain a deliberate rolling mix of roles such as cold discovery, series, proof, founder POV, question/community, search/depth, tool/demo, return/retention and product bridge. Do not hardcode percentages. Detect role imbalance and creative fatigue.

## 8. Series, not one lucky post

Use the smallest series/sample that can test the hypothesis. A viral outlier is evidence to investigate, not a permanent strategy. Growth can request specific assets from Content Factory only with a current hypothesis, channel-native job and acceptance.

## 9. Winner Amplifier

If a comparable asset materially beats baseline, trigger a bounded fast amplification packet: continuation, different hook/first-frame, native adaptation, top-comment follow-up, proof/tool/deeper version, series/profile connection. Preserve the proved mechanic intentionally; do not clone expression.

## 10. Loser Repair

Diagnose the first failed stage: discovery → open/stop → retention → participation/save/share → follow/profile → return → qualified action → sale. Repair that stage with `RE-HOOK / RE-PACKAGE / RE-CUT / RE-SEQUENCE / RE-TARGET / RE-DISTRIBUTE / HOLD / KILL`. Do not rewrite the wrong layer.

## 11. Native deployment and community

Define surface, format, CTA, IDs/UTM where applicable, evidence-backed timing, comments/messages follow-up and reuse rules. Comments/DM/questions are customer evidence. Reply usefully; do not disguise spam as help. Classify recurring evidence and route it back to Strategic Intelligence/Product/Content/Sales.

## 12. Retention, reactivation and owned audience

Where data exists, watch `NEW → RETURNING → REGULAR → QUALIFIED → CUSTOMER → REPEAT/DORMANT/UNFOLLOW`. Use series, pinned/start-here, useful updates, participation and lawful owned-audience capture when they reduce platform dependency without adding pointless funnel friction.

## 13. Collaboration / referral / earned distribution

Test co-created analysis, interviews, guest appearances, partner distribution, PR responses or referrals only when audience/value overlap and tracking are real. No mass partnership spam. Verify disclosure/rights/terms.

## 14. Funnel handoff

Every experiment knows the next honest step: profile, site article, product page, message, diagnostic/tool, checkout or another useful asset. If the commercial destination is not ready, use an honest intermediate measurable action.

## 15. Attribution and metrics

Track only available metrics relevant to the job:
`non-follower reach/opens / retention / saves / shares / comments / follows / unfollows / profile visits / repeat/return / clicks / product actions / checkout / leads / sales / revenue`.

Vanity metrics are intermediate. Large cold reach with no useful downstream movement is not automatically success.

## 16. Trend half-life

For time-sensitive growth use `half-life / SHIP-BY / minimum evidence / expiry condition`. Move fast by reducing unnecessary work, not by skipping fact/legal/brand gates.

## 17. Decision

After sufficient evidence choose:
`SCALE / AMPLIFY / FIX / ADAPT / REUSE / REPACKAGE / HOLD / KILL / AUTOMATE`.

Preserved legacy decision core for compatibility: `SCALE / FIX / ADAPT / HOLD / KILL / AUTOMATE`; r9 FINAL adds AMPLIFY/REUSE/REPACKAGE without removing the original states.

Automation becomes appropriate only after the routine/mechanic is stable.

## 18. Site CRO / subscription routes

After site analytics readiness, use behavior evidence for bounded CRO experiments. If club/subscription is activated, use the recurring-value operating loop in `growth-execution-operating-system.md`; follower count alone is not a launch criterion.

## 19. Learning loop

Update current Channel/Platform cards and playbooks from DOKRUTI evidence. Stable Skill promotion follows [Learning Promotion](learning-promotion-loop.md).

## 20. r8/r9 owner transaction bridge

Before a public asset is produced, choose one primary intended behavior: `STOP/OPEN / CONSUME / SAVE-SHARE / COMMENT-PARTICIPATE / PROFILE-SUBSCRIBE / SEARCH-CHANNEL-SITE / LEAD-PRODUCT`. Hook, format, media and CTA serve that behavior and current channel job; virality is a hypothesis, not a promise.

Content Factory receives actual comparable evidence where available. Missing metrics remain UNKNOWN. The owner-facing production/approval state machine remains [Unified Content Owner Transaction](content-owner-transaction.md).
