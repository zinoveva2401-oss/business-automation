# Product Value Integrity / Semantic Preservation

## Why this exists
A strong research idea can degrade into a weak 30-page product or a bloated 200-page product. Product Factory must preserve method and buyer value through every transformation.

## Two separate gates
1. `IDEA STRENGTH`: evidence, problem, differentiation, fit.
2. `PRODUCT STRENGTH`: the actual delivered artifact earns its price and changes user capability/decision.
Passing the first never passes the second.

## Semantic preservation ledger
Create stable `METHOD-ID`s for critical methods, mechanisms, limits, formulas, examples and counter-intuitive insights.
Track:
`ID / source / why material / blueprint location / final location / evidence / status`.

Critical required ID missing from final = release blocker. Editing for human language may change wording but not delete or distort method meaning.

## Value density
For each major section ask: what new thing does the buyer gain here?
Valid value units:
- distinction or causal model;
- decision rule;
- worked example/case;
- diagnostic/check/tool;
- failure mode/boundary;
- implementation move;
- evidence-backed surprising insight;
- connection that changes action.

Repeated framing, recap, paraphrase and decorative exercises do not count.

## AHA / surprise without hype
A paid intellectual product should repeatedly create honest recognition: `не знал / не связывал / теперь вижу причину / теперь понимаю что проверить`. Novelty must be useful and supportable, not forced sensationalism.

## Free-AI replaceability
Ask a skeptical buyer to compare against:
`free ChatGPT prompt / free article-video-template / software / consultant-hire / do nothing`.
If DOKRUTI adds no durable method, sequence, tools, examples, evidence, quality assurance or execution advantage, redesign before production.

## Long-book integrity
For 100–200+ pages check:
- first/middle/end depth parity;
- method coverage;
- narrative dependency;
- no repeated definitions/conclusions;
- examples distributed by learning need;
- tools bridge to exact actions;
- final integration/payoff;
- compression and expansion tests.

## Calendar-format restraint
Do not add 7/10/30-day plans as a generic product trope. Time-based cadence is allowed only when the mechanism genuinely requires repeated action/observation or it materially reduces implementation friction.

## Price/value check
Do not infer value from page count. Price hypothesis must be tested against outcome, alternatives, proof, completeness, support burden, distribution and economics.

## Release evidence
The final buyer-value verifier must inspect the actual product, not only blueprint or checklist.
