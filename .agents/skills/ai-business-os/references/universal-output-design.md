# Universal Output Design / Format-Native Presentation Contract

## Purpose

Professional presentation is required for every meaningful owner-facing, customer-facing or public artifact when presentation affects comprehension, action, trust or perceived value.

This contract is broader than e-book layout. It applies to:
- text posts, newsletters, emails/messages and visual posts/carousels;
- articles and web pages;
- landing/product/service pages;
- books, manuals, reports and research;
- PDF/DOCX documents, regulations, checklists, forms and templates;
- spreadsheets, workbooks and dashboards;
- presentations, commercial proposals and sales decks;
- product cards, START HERE and customer packages;
- diagrams, maps, matrices and owner-facing business artifacts;
- other client/public outputs where layout or formatting changes usability.

The goal is not decoration. The goal is `understand faster → trust more → act correctly`.

## 1. Classify the artifact before layout

Before production define:
- `AUDIENCE / USER`;
- `CUSTOMER JOB / COMMUNICATION JOB`;
- `TARGET SURFACE` — web, mobile, social feed, PDF, print, DOCX, spreadsheet, slides, messenger, email, etc.;
- `PRIMARY USE MODE` — READ / SCAN / DECIDE / DO / NAVIGATE / PRESENT / WATCH;
- `FIRST 5-SECOND MESSAGE`;
- `PRIMARY ACTION / NEXT STEP` if any;
- constraints: dimensions, screen, print, editability, file size, accessibility, platform limits;
- brand/source-of-truth requirements.

No layout begins until the use mode is clear.

## 2. Format follows function

Choose composition by semantic role, not by favorite component.

Examples:
- explanation/story → prose/editorial flow;
- short social insight → readable short-form hierarchy, not 15 isolated slogan lines;
- comparison → table/matrix only when columns genuinely help;
- process → sequence/timeline/flow;
- checklist → actionable checklist;
- regulation/SOP → numbered structure + roles + trigger + action + exception + evidence;
- form/template → obvious input zones + instructions + example only where useful;
- dashboard → decisions/alerts/priority first, raw data second;
- commercial proposal → problem/value/proof/offer/terms/next step;
- presentation → one dominant idea per slide/screen, speaker support rather than a pasted document;
- product card → promise + who/when + proof + contents/outcome + action;
- owner-facing strategy → map/matrix/flow when relationships matter;
- web navigation → findability and next action before decoration.

`CARD` is never a universal answer. Use it only for independent scannable units.

## 3. Universal hierarchy and typography

Every output must have intentional hierarchy:
- one obvious entry point;
- clear primary / secondary / tertiary information;
- readable body text for the target surface;
- consistent spacing rhythm;
- limited, semantic type hierarchy;
- alignment/grid that looks deliberate;
- emphasis by hierarchy before excessive colour, borders or badges;
- no tiny text used merely to fit more content;
- no decorative density that hides the action.

For Russian text, final proofing must check punctuation, quotation marks, nonbreaking relationships where needed, line breaks and orphaned headings/labels when the format exposes them.

## 4. Channel-native composition

Do not paste one layout into every channel.

### Text/social post / email / newsletter
- one clear thought or tension;
- natural paragraphs and semantic line breaks;
- no AI-style one-sentence-per-line spam unless intentionally used for a short rhetorical beat;
- hook must match the actual payoff;
- CTA only when the content/funnel role requires it;
- first visible screen must remain understandable without clickbait;
- email/newsletter/message hierarchy makes purpose, key information and next step obvious without ornamental layout.

### Visual post / carousel
- each frame has one dominant purpose;
- the sequence must build, not repeat the caption;
- type remains readable on a phone;
- visual system is consistent but frames may vary by function;
- final frame/CTA is not mandatory when the content role does not require it.

### Article / web reading
Use the specialized Publication Design contract when continuous reading is substantial.

### Presentation / sales deck
- one dominant message per slide;
- slide title states the takeaway where appropriate;
- charts/tables are simplified to the decision;
- no Word-document paragraphs pasted onto slides;
- speaker deck and send-ahead deck may require different density;
- actual 16:9/mobile/PDF export is rendered and checked as promised.

### PDF / DOCX / checklist / regulation / template
- function is obvious on page 1;
- editable fields are visually distinct when editing is expected;
- print margins/page breaks work when print is promised;
- references, footers, page numbers and navigation exist only when useful;
- PDF and DOCX are not duplicated without separate user jobs.

### Spreadsheet / workbook / dashboard
Use Product Experience contract for logic; visually:
- inputs, formulas/protected areas, outputs and alerts must be distinguishable;
- dashboard prioritizes decisions, exceptions and next actions;
- raw data is not the primary interface;
- number/date/percent formats are consistent;
- charts exist only when they improve a decision;
- actual Excel/Sheets target environment is opened and tested.

### Landing / product / service page
- first screen communicates audience/problem/value/next action;
- proof appears near the claim it supports;
- sections follow decision logic rather than a generic landing template;
- repeated card grids are reviewed for SaaS/template drift;
- desktop and mobile are intentionally composed.

### Owner-facing strategy / matrix / research
- show relationships, priorities, gaps and flow visually when they matter;
- decorative diagrams without decision value are prohibited;
- source master can stay textual, but owner-facing representation must be glance-readable.

## 5. Brand consistency without sameness

A shared brand does not mean every artifact uses the same card, grid or hero.
Freeze reusable rules:
`type roles / colour roles / spacing rhythm / image logic / icon/diagram logic / evidence treatment / CTA behavior / mobile behavior`.

Then adapt composition to the content job.
Consistency = recognizable logic, not cloned templates.

## 6. Real-content prototype before mass production

For a new substantial artifact class or materially new visual system:
1. build one representative piece/page/slide/screen with real content;
2. render in the target environment;
3. run content + design + usability critique;
4. freeze the pattern only after it works;
5. then scale production.

Do not mass-produce 30 pages/slides/cards before the representative output passes.

## 7. Actual-render QA

Specs and source files are not sufficient evidence.
Inspect the real output in the promised environment:
- text clipping/overflow;
- legibility at real size;
- crop/focal point;
- hierarchy and whitespace;
- page/slide breaks;
- mobile/desktop behavior;
- print/export if promised;
- editable fields if promised;
- link/navigation/action behavior;
- contrast/accessibility basics;
- brand consistency;
- file opening and portability;
- perceived value appropriate to the offer.

## 8. Anti-patterns

Major when material/repeated:
- card-everywhere;
- same template for every content type;
- tiny text / overcrowding;
- decorative icons where real evidence/tool preview is stronger;
- document pasted into slides;
- raw spreadsheet presented as a product interface;
- arbitrary colour changes instead of hierarchy;
- stock imagery with no communication role;
- every post broken into slogan fragments;
- visual complexity that makes the next action harder to find;
- one desktop composition merely squeezed onto mobile;
- duplicated formats with no separate customer job.

## 9. Independent presentation review

For substantial public/client output, the producer is not the sole approver.
A separate pass reviews:
`communication job / hierarchy / format-native fit / readability / semantic component choice / brand / accessibility / actual render / template risk / customer action`.

Return `PASS / FAIL / UNKNOWN` with concrete defects.

## 10. Relationship to specialized contracts

This contract is the universal baseline.
Add specialized contracts as needed:
- all customer-facing copy → Editorial / Human Language mode;
- substantial continuous reading → Publication Design / E-book / Long-form;
- new/material visual direction → Design Thinking / Visual System;
- workbook/client package → Product Experience / Artifact Architecture;
- web/code → Web Digital Asset + technical QA;
- video/motion/audio → [Media Production Quality](media-production-quality.md);
- legal/financial → domain precision gates override stylistic preferences when needed.

Professional design never changes facts, legal meaning or calculation logic merely for aesthetics.


## Brand/render integrity

Token/palette replacement is not visual-system verification. For materially branded outputs inspect the actual final render/composition/typography/rhythm against the current Brand/Product Design source and scan for legacy labels/tokens.
