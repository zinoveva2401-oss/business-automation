# Growth Execution Operating System | r9 FINAL

## Purpose

Convert strong intelligence and content capability into an evidence-driven audience and revenue operating loop. This module does **not** promise virality or follower counts. It makes growth programmable: define the target, calculate the required funnel, run a channel program, amplify winners quickly, repair losers by root cause, retain the right audience and connect public attention to real commercial outcomes.

Stable core stores the operating logic. Current platform algorithms, frequencies, surfaces and thresholds remain dynamic Platform Card / analytics facts.

## 1. Growth target math

For every material growth sprint translate the business target into the smallest observable funnel supported by real data:

`business target → qualified audience target → required discovery/non-follower reach → profile/channel entry → follow/subscribe → return/regular use → meaningful product/site action → lead/order/revenue`.

Use own account conversion rates first. If no baseline exists, mark rates `UNKNOWN`, establish the first baseline and use ranges/hypotheses rather than invented precision.

A goal such as `+1000 qualified followers` is an operating target, not a guarantee. The system must show which upstream rates are limiting the target and what experiment is intended to move them.

## 2. Channel program, not isolated posts

Treat an active channel as a media product with a deliberate weekly/rolling portfolio. Content roles may include:

`COLD DISCOVERY / SEARCH / TRUST / PROOF / FOUNDER POV / SERIES / QUESTION-PARTICIPATION / COMMUNITY / TOOL-DEMO / CASE / TREND REACTION / PRODUCT BRIDGE / RETURN-RETENTION / COLLAB`.

Do not hardcode universal percentages. Build the mix from the current channel job, maturity, audience state and evidence. The system should notice role imbalance, for example: all education and no discovery; all reach and no subscribe reason; all sales and no trust; all founder POV and no proof.

## 3. Winner Amplifier

When an asset materially outperforms its comparable baseline, do not simply log success and move to an unrelated topic.

Create a bounded amplification packet while the evidence window is still useful:
- continuation/part 2;
- materially different hook/first frame for the same useful idea;
- native adaptation for another justified surface;
- response to top audience question/objection;
- deeper proof/case/tool version;
- profile/pinned/series connection that increases reason to follow;
- commercial bridge only when the destination is ready.

Record what is being preserved: `topic / audience / mechanic / proof / visual grammar / CTA / timing`. Change deliberately, not randomly.

## 4. Loser Repair Loop

A weak result is not one generic `KILL`.

Diagnose the first failed stage in the actual funnel:
- weak discovery/impressions → distribution/eligibility/topic/packaging hypothesis;
- impressions but weak open/stop → hook/cover/first-frame problem;
- open but weak retention/read-through → structure/pacing/payoff problem;
- consumption but weak save/share/comment → usefulness/emotion/participation problem;
- strong consumption but weak follow/profile move → subscribe reason/series/profile packaging problem;
- followers but weak return → retention/program problem;
- attention but weak qualified action → CTA/offer/destination mismatch;
- qualified action but weak sale → commercial route/offer/checkout/delivery issue.

Then choose `RE-HOOK / RE-PACKAGE / RE-CUT / RE-SEQUENCE / RE-TARGET / RE-DISTRIBUTE / HOLD / KILL`. Do not repeatedly rewrite the body when the failed stage is packaging or channel fit.

## 5. Creative portfolio and fatigue memory

Dedupe must cover not only topic text but also creative grammar. Track, where useful:
`hook family / first-frame type / narrative form / composition / motion device / founder presence / proof type / CTA / series / sound or audio mechanic`.

If recent output overuses the same grammar, intentionally challenge with a materially different route. Repetition is allowed for a proven recognizable series; accidental sameness is not.

## 6. Trend half-life / SHIP-BY

Fast signals require a time decision. A signal card may include:
`half-life / evidence freshness / SHIP-BY / minimum viable evidence / minimum viable production / expiry condition`.

Do not spend three days perfecting a response to a one-day signal. Equally, do not bypass fact/legal/brand gates merely because a trend is fast.

## 7. Return, retention and reactivation

Follower count is not the endpoint. Track available cohorts/states:
`NEW → RETURNING → REGULAR → QUALIFIED → CUSTOMER → REPEAT / DORMANT / UNFOLLOW`.

Use real platform/site/customer evidence to test:
- recurring series and recognizable programming;
- pinned/start-here routes;
- next-part promise only when it will actually be delivered;
- updates to previously useful assets;
- reply/comment participation;
- newsletter/owned-channel capture where appropriate and lawful;
- reactivation messages only where consent/channel rules permit.

Do not optimize for low-fit followers who immediately ignore, leave or damage trust.

## 8. Community → Content → Product loop

Comments, replies, questions, objections, searches and support interactions are production inputs.

Classify recurring evidence into:
`CONTENT FOLLOW-UP / FAQ / PROFILE-PACKAGING DEFECT / SALES OBJECTION / PRODUCT OPPORTUNITY / SERVICE OPPORTUNITY / SUPPORT DEFECT / NOISE`.

Update existing canonical objects. Do not create a new idea/task for every comment.

## 9. Collaboration / referral / earned distribution

Growth is not restricted to own posting cadence. When audience/brand fit exists, test lawful:
`expert collaboration / co-created analysis / guest contribution / interview/podcast / partner distribution / community appearance / referral loop / customer-member referral / PR response / useful syndication`.

Each route requires real audience overlap, role/value exchange, rights/disclosure where applicable, tracking and a reason not to do it. No mass-spam partnership outreach.

## 10. Owned-audience bridge

Where strategically useful, reduce dependence on one algorithm by creating a lawful path to owned or more controllable assets: site/search/library/email/newsletter/customer base/community/product account. Do not force people through extra steps only to capture them.

## 11. Site CRO / behavior loop

After production site release and analytics readiness, site design enters a behavior loop:
`session/event evidence → friction hypothesis → bounded experiment → result → adopt/adapt/reject`.

Useful evidence may include route exits, scroll/interaction, failed CTA, form errors, search behavior, replay/heatmap only when privacy/consent/tooling permit, and downstream conversion/revenue. A visually attractive section is not automatically a good conversion surface.

## 12. Club / subscription operating loop

If DOKRUTI activates a paid/free closed channel, club or subscription, operate it as a recurring-value product:
`promise → onboarding → first value → recurring program → library/navigation → participation/community → renewal/return → churn reason → referral → product/service bridge`.

Do not launch a subscription only because audience size reached a round number. Require recurring value capacity, delivery economics, moderation/support route and measurable retention.

## 13. Daily/rolling decision packet

When enough evidence exists, the system should proactively say what to do next, for example:
`AMPLIFY WINNER / REPAIR HOOK / PRODUCE PART 2 / CHANGE FORMAT / FIX PROFILE / ANSWER COMMENT AS CONTENT / RUN COLLAB TEST / HOLD SALES CTA / UPDATE PLATFORM CARD / STOP LOW-FIT SERIES`.

Owner sees the decision and evidence, not a raw analytics dump.

## 14. Learning destination

Store dynamic channel findings in the Channel/Platform Card or current Growth playbook. Promote only durable cross-task principles into stable Skill via the Learning Promotion gate.
