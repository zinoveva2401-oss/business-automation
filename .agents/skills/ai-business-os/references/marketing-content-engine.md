# Marketing Matrix + Integrated Content Factory v2.0.10

## 1. Entry gate

A meaningful content run can start from:
- an evidence-backed Opportunity Card from Strategic Intelligence;
- an existing analytically strong Content System row whose current brand/product/commercial truth has been rechecked; or
- a raw founder input: rough idea, voice note, field observation, customer scene, question, source, screenshot, media folder or “I noticed this today”.

Raw founder input is **not** permission to immediately create a new Content System row. First run entity/dedupe resolution against existing content/tasks. Then transform the idea into a content/opportunity route.

Do not research from zero when the evidence is already valid. Recheck dynamic facts/platform rules immediately before production.

A compact content brief must contain, as applicable:
`business objective / exact audience+situation / one pain-question-tension / content job / awareness state / one payoff / evidence / current brand-product truth / primary format+channel / founder voice / CTA or next step / primary metric / legal-claim risk / source freshness`.

## 2. Content Factory workflow

`raw idea/signal/opportunity → entity/dedupe resolution → current-fit gate → business mechanism + content job → useful implementation/payoff → evidence/freshness pack → 2–4 materially different creative/format routes when needed → strongest-route challenge → SPEC PASS → master production → creative/editorial/media QA → result amplifier + repair → native adaptations → cover/thumbnail/profile handoff where applicable → search/discovery layer → independent publication gate → publish/distribute → URL/object readback → community/VOC → measurement → SCALE/FIX/REUSE/REPURPOSE/KILL → product/service/money/intelligence learning write-back`.

For substantial creative work use [Creative Content Production / Second Creative Brain](creative-content-production.md).

## 3. One pain, not one template

By default one content unit goes deep on one narrow pain/question/decision and gives one clear payoff. This does NOT mean identical article structure.

Allowed narrative forms include story, case teardown, comparison, experiment, researched founder observation, error/reversal, screen demo, visual explanation, practical move or long-form analysis.

Do not use the Awareness/Hunt ladder or any other framework as the mechanical template for every article.

## 4. Primary format follows the job

Choose/challenge the primary format before writing. Candidate set is open-ended and task-driven, including:
short native post / site-search article / native long-form / vertical video / talking-head / screen demo / documentary-B-roll / motion-carousel / animated still / carousel/visual explanation / founder story / comparison/review / mini-tool-checklist-calculator / commercial bridge / experiment probe / hybrid content+tool.

Do not obey the originally requested medium blindly when a materially stronger route exists. Explain the stronger route and produce a fast representative prototype when that resolves the choice without a true owner gate.

A SITE MASTER is required only when a durable owned search/knowledge asset is actually the best primary object. Social-first/video-first/demo-first content may be the master.

## 5. Founder voice

Default voice is practitioner-researcher:
`noticed → investigated → compared → chose/adapted → explain why → show what to do/test`.

Do not invent personal results/cases. Expertise is demonstrated by the quality of evidence, synthesis and decision, not repeated “надо делать так”.

## 6. Developmental value gate

Fresh-context review checks:
`real question → development → payoff / depth / specificity / evidence-example / authorial synthesis / useful next step`.

If a generic AI prompt could replace the material with little loss, FAIL.

Then run the full [Editorial / Human Language / Reader Experience Contract](editorial-reader-experience.md): natural Russian, varied rhythm/structure, transitions, anti-AI-slop and continuous read-through.

## 7. Fact / claim / donor / IP

Check important facts, figures, dates, interfaces, causal claims and attribution. Strong public ideas can donate mechanics/principles, never protected expression/design/code 1:1. Do not present synthesis as a novel invention when attribution/provenance matters.

## 8. Creative / visual / video intelligence

Visuals must either explain, demonstrate or create a content-specific stopping event. Repeated generic stairs/arrows/cards are not sufficient. Scale production effort to the format.

For substantial social/video content explicitly design the **first visual event**, hook/payoff integrity and cover/thumbnail when the surface uses one. Static is not the default; motion is not the default.

Video route includes producer/director logic, source plan, first-frame, shots/B-roll/screen/graphics, founder shoot-card when needed, captions, voice/sound/music, edit rhythm, first-cut→critique→repair, safe areas, export, cover/thumbnail and real playback QA. Use `creative-content-production.md` + `media-production-quality.md`.

## 9. Native adaptation

Do not produce five versions merely because five channels exist. Each adaptation must have a real channel-native job/audience/CTA/mechanic. Verbatim cross-post is acceptable only when the surface and audience genuinely match.

## 10. Search/discovery

For search assets: intent, useful fast answer, H1/title/meta/slug, structure, internal links, canonical/indexability, current sources and structured data where actually applicable. SEO does not dictate prose.

For social/video: use the natural language of the problem, a strong first screen/cover and accessible captions/alt where useful.

## 11. Independent publication gate

Producer self-PASS is invalid for substantial public assets. A separate/fresh-context review checks actual text/render/video for:
- factual/claim error;
- weak payoff or generic content;
- artificial/template prose;
- stale brand/product/CTA;
- broken link/action;
- unreadable/irrelevant visual;
- missing required native output;
- privacy/IP/platform risk.

Opportunity improvements do not block once acceptance is met; Critical/Major defects do.

## 12. Publication evidence

`PUBLISHED ≠ PUBLISHED VERIFIED`.

After publishing read back the actual URL/object/version/access/title/visual/CTA and UTM/identifier when applicable. If the URL/object is missing or inaccessible, the stage remains incomplete.

## 13. Community and VOC

Comments, questions, messages, objections and search terms are new customer evidence. Prepare owner-light responses and escalate only where Svetlana's personal voice/decision is truly needed. Repeated questions feed Strategic Intelligence/Product/Sales.

## 14. Measurement by role

Metric follows content job, not vanity:
reach/discovery, retention/read-through, saves, shares, comments, follows, profile movement, clicks, product clicks, checkout, leads, sales, revenue, support questions, etc. Use only metrics actually available.

No universal fixed measurement window: fast social/video, evergreen search, commercial probes and founder/trust content have different evidence horizons.

## 15. Learning decision

After sufficient evidence choose:
`SCALE / FIX / REUSE / REPURPOSE / HOLD / KILL / ARCHIVE`.

Write actual results back to the current Content System/analytics and return strong/weak signals to Strategic Intelligence, Product and Money loops.

## 16. Product/content/service bridge

Product pains/opportunities can generate search/social/video/content clusters. Conversely, a founder observation or repeated audience response can expose a **product/service opportunity**.

Content Factory does not silently freeze product strategy, price or offer. It must:
1. check existing Product/COMM-ARCH records first;
2. capture the opportunity without duplicate task creation;
3. gather lightweight competitor/free-alternative/VOC evidence;
4. route the opportunity to Product Factory / COMM-ARCH;
5. continue only the content value that stands on its own.

Content can also disconfirm a product/service hypothesis before expensive build.

## 17. Affiliate/recommendation content

Affiliate remains layer 2 after independent usefulness. Verify current terms, disclosure/platform/legal rules and who the recommendation is not for. No grey moderation-evasion schemes.

## 18. Weak idea rescue + visual command trigger

A weak raw idea is not automatically a weak output. Before KILL, Creative Brain runs the rescue ladder in `creative-content-production.md` and tests whether the value becomes stronger through another angle/audience/format/proof/mechanism.

When visual/form representation would materially improve understanding or stopping power, automatically route through the quick-command palette. The owner does not need to remember command names. Show only the 1–3 most useful representations and a short preview of how each would look.

## Content as proof and product mining

Content should not only acquire attention. When a topic emerges from DOKRUTI's real implemented work, connect it to `proof artifact → practical lesson → reusable method → possible product/service hypothesis`, while keeping research/learning distinct from a proven customer offer. Use [knowledge-capital-product-mining.md](knowledge-capital-product-mining.md) and dedupe against the existing product hypothesis bank.


## 19. r8 Unified Owner Transaction

This module executes under [Unified Content Owner Transaction](content-owner-transaction.md). The public Content Factory is one owner-facing job, even when several internal competencies/tools are used. A `VISUAL BRIEF` is not a finished visual. A short owner command must recover the live queue and produce a complete review-ready platform asset before asking for approval.

For DOKRUTI public content, internal QA precedes the owner gate. `На утверждении` is not publishable. After explicit owner approval, Business OS freezes the exact payload, writes/readbacks it in the existing output row, materializes required media and only then sets `Запланировано` for Publisher.

When current creative intelligence matters, prefer transferable donor mechanics/evidence from fresh Russia + international + China/Asia/platform/creator sources, but transform them into original DOKRUTI execution. Current success of a mechanic is a test signal, not a permanent algorithm rule.


## 20. r8 editorial depth guard

One public unit normally carries one strong thought and one micro-value rather than a complete free mini-course. In any five consecutive publications, normally no more than two are direct how-to/diagnostic pieces unless current evidence supports a bounded exception. Use the current editorial-role mix to build attention/trust/subscription/authority, not only instruction. Preserve the honest boundary between useful free content and the full methodology/templates/implementation cycle of an active paid product/service.

## 19. Founder Voice Corpus / Voice Drift | r9 FINAL

For founder-led public content, “human language” is necessary but not sufficient. Maintain a compact, consented corpus of real Svetlana language from approved messages, voice transcripts, edits and published materials. Store **patterns**, not unnecessary personal/raw history:
`sentence rhythm / preferred directness / characteristic transitions / practical vocabulary / taboo clichés / acceptable emotion / profanity policy by surface / how uncertainty is stated / how examples are told / CTA style`.

Before owner handoff run `VOICE DRIFT`: could this be a generic competent AI/expert after swapping the name? If yes and founder voice is required, repair. Do not imitate accidental speech errors or fabricate life stories/results.

## 20. Channel-program context

Content Factory must know not only the next topic but the current channel program role from Growth. The same good idea may be wrong today if the channel currently lacks discovery, return, proof or subscribe reason. Use [Growth Execution Operating System](growth-execution-operating-system.md).

## 21. Winner amplification and loser repair handoff

When Analytics/Growth marks an asset `AMPLIFY`, Content Factory creates the bounded continuation/adaptation packet before returning to unrelated queue work. When marked `REPAIR`, change the failed layer (hook/cover/pacing/profile/CTA/etc.) rather than automatically rewriting the whole master.

## 22. Creative fatigue gate

Before producing another public asset, compare recent `hook family / narrative form / first-frame / visual grammar / founder presence / proof type / CTA`. A proven series may repeat deliberately; accidental repeated AI grammar triggers a materially different creative challenge.
