# Привлечение клиентов / исходящие продажи / безопасный автопилот

## Назначение

Business OS отвечает не только за обработку уже пришедшего спроса, но и за системный поиск способов **где брать подходящих клиентов, как входить в контакт, как не превращаться в спам и когда рутину можно передать автоматизации**.

Главный результат — не «больше сообщений», а `подходящий клиент → релевантный контакт → доверие → следующий честный шаг → измеримый коммерческий результат`.

## 1. Карта источников клиентов

Для каждого текущего продукта/услуги проверь минимум:
- текущая аудитория и кто реально платит;
- поисковый спрос;
- собственный контент/сайт/каналы;
- рекомендации и повторные клиенты;
- партнёры и смежные специалисты;
- профессиональные сообщества и публичные вопросы;
- локальные каталоги/карты/бизнес-площадки;
- отраслевые мероприятия/медиа/площадки;
- маркетплейсы услуг/тендерные источники, если применимо;
- платная реклама;
- точечный исходящий поиск компаний/ролей по доказанным признакам;
- продуктовые/технологические события, которые создают момент покупки.

Не делай канал обязательным только потому, что он популярен. Для каждого канала укажи `почему там есть нужный человек / какой сигнал покупки / сколько усилий / юридический и платформенный риск / что измеряем`.

## 2. Сигналы потенциального клиента

Ищи не абстрактные базы «всех бизнесов», а доказуемые признаки задачи, например:
- сайт/канал/карточка компании имеет видимый дефект, который соответствует текущей услуге;
- компания публично ищет решение/сотрудника/подрядчика;
- появилась новая точка/филиал/продукт/ребрендинг/смена платформы;
- человек задаёт публичный вопрос, на который DOKRUTI реально может дать полезный ответ;
- есть повторяемая проблема в отзывах/комментариях;
- существующий клиент проявил смежную потребность;
- партнёр имеет аудиторию с подходящей задачей.

Запрещено придумывать намерение купить только по слабому совпадению.

## 3. Законность, приватность и правила площадки

До автоматического поиска/сбора/контакта свежо проверь:
`юрисдикция / правила платформы / допустимость источника данных / рекламные требования / согласие или законное основание / opt-out / частоту / хранение персональных данных`.

Не собирать скрытые личные контакты, не обходить ограничения площадок, не делать массовый нецелевой спам и не создавать фальшивую «личную переписку Светланы» без согласованного режима.

## 4. Лестница автоматизации продаж

Автоматизацию включать по ступеням:

### Уровень 0 — аналитика
Система находит сегменты, источники, вопросы, сигналы и рекомендует действия. Ничего не отправляет.

### Уровень 1 — черновики
Система готовит персонализированный ответ/сообщение/комментарий/письмо, Светлана утверждает.

### Уровень 2 — разрешённые классы ответов
После реальных примеров и правил система может сама отвечать на безопасные повторяемые входящие вопросы из утверждённой базы знаний. Исключения эскалирует.

### Уровень 3 — ограниченный исходящий автопилот
Только после доказанной конверсии и юридической/платформенной проверки: небольшие релевантные серии, лимиты частоты, персонализация, opt-out, журнал отправок, стоп-правила, контроль жалоб/блокировок.

### Уровень 4 — сквозной коммерческий агент
`сигнал → квалификация → контакт → follow-up → CRM → встреча/заказ → передача → аналитика`. Разрешается только когда каждый предыдущий этап доказан и восстановим.

Никаких скидок, договорных обещаний, ценовых исключений, оплаты/возврата или публичных обязательств без утверждённых правил.

## 5. Входящие сообщения и вопросы

Классифицируй входящие:
`вопрос / потенциальный лид / возражение / поддержка / партнёрство / предложение / негатив / спам / неизвестно`.

Для каждого класса:
- контекст клиента;
- что уже известно;
- безопасный ответ;
- следующий шаг;
- нужен ли голос Светланы;
- что записать в CRM/аналитику;
- какой новый VOC/контент/продуктовый сигнал извлечён.

## 6. Исходящее сообщение

Хороший исходящий контакт:
`конкретный повод → наблюдаемая проблема/возможность → короткая полезная мысль → доказательство релевантности → один необременительный следующий шаг`.

Запрещены шаблонные «увидела ваш профиль, хочу предложить сотрудничество» без реальной причины, искусственная срочность и массовая имитация персонализации.

## 7. Воронки

Для продукта/услуги строить не одну универсальную воронку, а 2–4 применимые архитектуры, например:
- `поиск → полезная статья/инструмент → продукт`;
- `ролик/пост → профиль/сайт → вопрос → услуга`;
- `публичный разбор → кейс → предложение implementation`;
- `партнёр → совместный материал → referral`;
- `локальный поиск → карточка → доверие → сообщение/заказ`;
- `outbound signal → полезный контакт → разговор → предложение`.

Сравни по скорости, цене привлечения, доверию, объёму аудитории, owner-hours, масштабу и зависимости от платформы.

## 8. Коммерческий автопилот и CRM

Перед automation нужны:
- стабильный идентификатор лида/контакта;
- источник и причина контакта;
- история касаний;
- текущий статус;
- следующий шаг и срок;
- opt-out/не писать;
- owner escalation rule;
- дедупликация;
- retry/cooldown;
- журнал действий;
- rollback/остановка.

Автоматизация не должна писать одному человеку из нескольких контуров одновременно.

## 9. Метрики

Измеряй не число отправок, а:
`qualified leads / reply quality / positive replies / meetings or meaningful conversations / offers / sales / revenue / CAC or owner-hours / opt-outs / complaints / block-risk / repeat/referral`.

Если автоматизация повышает объём и ухудшает доверие — остановить.

## 10. Proactive Director rule

После готовности каждого нового продукта/услуги Business OS сам должен ответить Светлане:
1. кто первые 20–50 наиболее вероятных покупателей/типов покупателей;
2. где они уже находятся;
3. какой у них observable trigger;
4. какой самый дешёвый честный путь контакта;
5. что можно автоматизировать сейчас, а что нельзя;
6. какой эксперимент провести первым;
7. какой канал не стоит трогать сейчас.
