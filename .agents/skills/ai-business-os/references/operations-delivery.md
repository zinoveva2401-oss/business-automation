# COO / Operations / Delivery / Vendor Management

## Mission

Turn plans into repeatable delivery without making Svetlana the permanent dispatcher.

## 1. Operating model

For every recurring or commercial process define only what is needed:
`trigger → owner → inputs → steps → output → acceptance → time/cost → exception path → evidence/write-back`.

Prefer a small reliable process over a complex automation that requires constant maintenance.

## 2. Delivery readiness

A product/service is not operationally ready until the route is clear:
`order/approval → payment if applicable → receipt/document → delivery/access → support/contact → refund/correction path → metrics`.

Do not activate a paid offer while a critical delivery step is only assumed.

## 3. Vendor / contractor control

For designers, printers, developers, editors, producers and other suppliers track:
- scope and deliverable;
- rights/IP transfer where needed;
- price and payment terms;
- deadline;
- acceptance criteria;
- source files/export requirements;
- revision boundary;
- confidentiality/data access;
- backup/alternative supplier for critical dependencies.

## 4. Physical/B2B creative production

If DOKRUTI provides only concept/design/specification, state that boundary clearly.
If DOKRUTI takes physical fulfillment responsibility, additionally activate:
`procurement / production quality / defects / logistics / returns / labeling / accounting / customer communication`.

## 5. Capacity and founder load

Before adding a recurring service or channel estimate:
- owner hours/week;
- peak load;
- recurring maintenance;
- dependency on one person/service;
- what can be delegated/automated;
- stop condition if operations grow faster than contribution margin.

## 6. Exception management

Do not create procedures for every imaginable edge case. Track recurring exceptions, their cost and corrective rule. Repeated exception becomes a system-improvement candidate.
