# Sales / Money / Delivery / CRM / Customer Success / Attribution v2.0.9

## Purpose

Turn qualified intent into correct payment, delivery, first value, financial write-back and learning. A button or successful payment alone is not a completed sale.

## 0. Demand generation / где брать клиентов

До обработки уже пришедшего намерения прочитай [Привлечение клиентов / исходящие продажи / безопасный автопилот](sales-demand-generation-autopilot.md). Sales отвечает не только за checkout: для текущего продукта/услуги должна существовать доказанная карта источников клиентов, сигналов спроса, inbound/outbound/partner routes и допустимого уровня автоматизации.

## 1. READY-TO-SELL gate

A public sale is allowed only for one current verified SKU/offer with, as applicable:
`verified product / factual price+terms / offer surface / legal+claims / data flow+consent / payment / receipt-tax scenario / CRM-or-source record / verified delivery artifact+permissions / START HERE / support route / analytics events / refund+failure route`.

Any Critical missing item → `PUBLIC SALE BLOCKED`.

## 2. Intent and qualification

Capture source/content/campaign plus the problem the person is trying to solve. Do not force the buyer to repeat known context.

Route to: current product / another solution / free resource / human conversation / no-fit. Do not mis-sell for conversion.

## 3. Offer truth

Use only a current verified offer source for problem, outcome, mechanism, scope, format, price, delivery, boundaries, proof, who-not-for, support/update terms and CTA.

No fake scarcity/reviews or unsupported ROI/outcome claims.

## 4. Checkout / payment / receipt

Before payment show final amount and terms. Use unique order/payment identity and duplicate-submit/fulfillment protection. Track success/fail/pending separately.

Tax/receipt/accounting behavior follows the actual legal/business/payment setup and must be fresh-verified before launch or material changes.

## 5. Delivery integrity

After confirmed payment deliver only the current VERIFIED SEND ONLY artifact/access. Verify filename/version/permissions/link route and include START HERE/support.

`PAYMENT SUCCESS + DELIVERY FAIL = Critical incident`.

Do not close the run until customer access is restored or the incident is routed under an approved recovery rule.

## 6. Activation / first value

A download is not automatically value. Define the first useful product action and, where lawful/technically reasonable, collect transparent evidence/proxies that the buyer can start and understands the next step.

Do not add hidden telemetry to offline files by default.

## 7. Minimal CRM boundary

The Business System is a control layer, not a random personal-data warehouse. When a true CRM is justified, compare data/legal fit, export, API/webhooks, cost, automation burden and integrations.

Store only data actually needed and permitted.

## 8. Attribution/event dictionary

Keep stable source/content/product/offer/order identifiers where applicable so the business can answer:
`where customer came from → meaningful action → offer → purchase → delivery → first value → refund/repeat → revenue/cost`.

Avoid premature complex multi-touch attribution when a simpler reliable model answers the decision.

## 9. Failure recovery

Explicitly handle states such as:
`paid-not-delivered / pending payment / duplicate order / broken link / wrong version / receipt failure / CRM write failure / refund request`.

Automation must not silently change price, grant large discounts, return money, make legal exceptions or perform another high-impact action outside approved rules.

## 10. Customer Success / outcome

Questions, friction, time-to-first-value, usage/check-ins, result, satisfaction, review/recommendation, refund and repeat demand feed back to Product/Content/Sales/Strategic Intelligence.

Distinguish product defect, learning gap and user-specific situation.

## 11. Money write-back

Record confirmed money facts in the current finance/analytics sources: product/order/source, gross revenue, payment fee, refund, tax/variable cost where available, contribution estimate and owner/support time where useful.

Revenue remaining only inside a payment provider is an incomplete loop.

## 12. Commercial learning

Analyse source→content→offer→checkout→payment→delivery→activation→outcome→repeat plus margin/support load.

Decide `SCALE / FIX / PAUSE / RETIRE / REPOSITION` from evidence, not sunk cost.
