# Global Creative & Product Intelligence | r9

## Mission

This module turns Radar from a small set of topical searches into a permanent **global creative, product and market-intelligence engine** for DOKRUTI.

It extends — and does not replace — `global-intelligence-radar.md`, `research-competitive-intelligence.md`, `strategic-intelligence-opportunity.md`, `content-owner-transaction.md`, `experiments-analytics.md` and `learning-promotion-loop.md`.

Canonical chain:

`SOURCE UNIVERSE → GLOBAL SCOUTING → RAW OBSERVATIONS → CANDIDATES → STRONG DONORS → SIGNALS → DOKRUTI ADAPTATIONS → MONEY ROUTES → EXPERIMENTS → LEARNING`.

The objective is not “collect more trends”. The objective is to create an **information advantage**: notice working mechanics early, distinguish evidence from hype, find Russian-language whitespace, convert a donor into original DOKRUTI moves, and propose cheap measurable tests before the opportunity becomes banal.

## 1. Source Universe — permanent source map

Radar must maintain a dynamic map of source families instead of searching only “by the current query”. The map may live in an existing canonical competitor/reference/playbook object or current Business/Content System. **Do not create a parallel Radar / Signals / Ideas database just to support this module.**

Each source-family card should know, when material:

`source family / geography / domain / access route / cadence / freshness / evidence type / legal-or-access constraint / historical signal yield / last checked / current blind spot`.

Minimum source families:

1. **Culture / viral / creator** — short video, long video, social posts, newsletters, meme/culture, visual discovery.
2. **Products / launches** — digital products, B2B tools, AI products, creator products, SaaS, marketplaces, templates, courses, productized services, crowdfunding/launch ecosystems.
3. **Ads / offers / funnels** — ad libraries where lawful/available, landing pages, bundles, pricing, guarantees, lead magnets, productized-service packaging, creator funnels.
4. **SMB pain / audience language** — reviews, comments, forums, communities, search questions, complaints, product reviews, entrepreneur discussions.
5. **Search / demand** — current search trends, rising queries, autosuggest/questions, SEO/AEO changes and available first-party search evidence.
6. **China / Asia / social commerce** — social selling, livestreaming, marketplace, creator-commerce and messaging-commerce mechanics where sources are accessible and verifiable.
7. **AI / platform / automation** — platform changes, AI products, agents, APIs, connectors, new production/distribution capabilities.
8. **Cross-industry wildcard** — sources outside consulting/business content chosen deliberately for serendipity.

Named services/platforms are examples, not permanent dependencies. Before relying on them, fresh-check availability, access, geography, terms and evidence quality.

## 2. Global Scouting — separate geographical lenses

A “global scan” cannot be one English-language search. When the task is broad enough, scout separate lenses:

- `US / NORTH AMERICA`;
- `EUROPE / UK`;
- `CHINA / EAST + SOUTH-EAST ASIA`;
- `RUSSIA / RUSSIAN-SPEAKING MARKET`;
- `WILDCARD / OTHER REGION OR INDUSTRY` when it can reveal an adjacent mechanic.

For each lane record either evidence or an explicit `COVERAGE GAP`. Do not imply global coverage when only one region was checked.

## 3. High-input → low-output scouting funnel

Radar must have a large input and a small output. Under sufficient time/tool budget, target this shape:

`100+ RAW OBSERVATIONS → ~30 CANDIDATES → ~10 STRONG DONORS → 3–7 SIGNALS → 1–3 TESTS`.

This is a **funnel shape**, not a ritual quota. Daily work may stop earlier when marginal new evidence is saturated, sources are inaccessible or the request is narrow. But `3 sources → 3 conclusions` is not enough for a broad market/creative Radar unless the limitation is explicitly reported as `INSUFFICIENT SCOUTING / COVERAGE GAP`.

The owner sees the shortlist, not the raw dump.

## 4. Seven mandatory donor types

Radar searches not only for topics, but for concrete donors. Each meaningful cycle should consider the seven donor classes relevant to the task:

1. `DONOR PRODUCT` — a product that can be rethought, decomposed or productized differently.
2. `DONOR OFFER` — an unusual promise, packaging, bundle, guarantee, entry point or pricing mechanic.
3. `DONOR CONTENT` — a specific strong post/article/video/series with observable evidence.
4. `DONOR FORMAT` — repeatable structure: teardown, challenge, experiment, POV, serial story, screen test, build-in-public, etc.
5. `DONOR HOOK` — first-line, first-frame, visual stopper, tension/reveal or opening construction.
6. `DONOR BUSINESS MODEL` — subscription, licensing, B2B pack, audit-as-product, white-label, paid media, marketplace, etc.
7. `DONOR DISTRIBUTION` — a new or underused acquisition/distribution loop.

For every strong donor, capture:

`WHAT IT IS → SOURCE+DATE → EVIDENCE/TRACTION → WHY IT WORKS → TRANSFERABLE MECHANIC → WHAT WE TAKE → WHAT WE DO NOT COPY → ORIGINAL DOKRUTI ADAPTATION → FAST TEST → METRIC → PROVENANCE/RISK`.

Protected expression, distinctive design, full copy, paid material and other IP are never transferred 1:1.

## 5. Viral-content mining — concrete assets, not generic “trends”

When content/growth is in scope, search for **specific assets and repeatable series**, not only topic reports. Extract, where observable:

`hook / first-frame stopper / promise / tension / reveal / proof / pacing / shot-or-screen logic / text-audio relationship / comment loop / save-share trigger / serial mechanic / CTA / distribution path / audience response / source+date`.

Do not call something “viral” solely because the absolute view count looks large. Compare against available creator/channel baseline, recency, repeated pattern, velocity or multiple examples. If those are unavailable, label the claim `VIRALITY PROXY`, not fact.

## 6. Trend Velocity — stage and speed

Every material trend/mechanic receives a current stage when evidence allows:

`EMERGING / ACCELERATING / MAINSTREAM / SATURATED / DECLINING / UNKNOWN`.

Store:

`stage / evidence window / direction or proxy / saturation signal / confidence / next recheck`.

A trend label without a time window is weak evidence. Historical popularity must not be presented as current acceleration.

## 7. Localization Arbitrage — mandatory RU-gap pass

For every strong non-Russian donor, ask explicitly:

> **Это уже растёт/работает в мире, но ещё не стало банальностью в русскоязычной бизнес-среде?**

A localization-arbitrage candidate must pass four checks:

1. `GLOBAL TRACTION` — there is current evidence that the mechanic/product/offer works or is accelerating somewhere.
2. `RU GAP` — an explicit Russian-language market scan shows lower saturation, missing adaptation, weak execution or unresolved buyer friction. “I did not see it quickly” is not proof of whitespace.
3. `TRANSFER FIT` — cultural, regulatory, channel, buyer and production conditions allow an original DOKRUTI version.
4. `TESTABILITY` — a cheap/reversible test can validate the hypothesis before large investment.

Mandatory translation:

`SIGNAL → MECHANIC → RU GAP → DOKRUTI ADAPTATION → TEST`.

Low Russian competition does not automatically mean demand. Label whitespace and demand separately.

## 8. Audience-Language Mining — real words of the market

Continuously mine real buyer language from lawful/available public or first-party sources: comments, reviews, forums, communities, product complaints, search questions, YouTube comments, entrepreneur discussions and analogous sources.

Capture compactly:

`problem phrase / desired outcome / objection / failed workaround / emotional wording / trigger / buyer stage / source+date`.

Separate verbatim evidence from synthesis. Do not fabricate prevalence from a few comments. Respect quotation/copyright limits; the purpose is language intelligence, not copying long source text.

## 9. Creative Mechanics Library + Swipe Bank

Strong donors become **mechanic cards**, not folders of copied content. Recommended card:

`mechanic ID / donor type / source+date / audience / hook / sequence / mechanism hypothesis / observable proof / production complexity / risks / suitable channels / original DOKRUTI variants / experiment result / status`.

Useful families include, but are not limited to:

`reveal / teardown / POV / roleplay / before-after / screen test / challenge / serial story / founder process / live diagnostic / comments-loop / visual proof / comparison / build-in-public / documentary B-roll / data explanation`.

A card is a candidate mechanism, not a universal rule. Keep failed/rejected cards searchable so the system does not rediscover the same dead end.

## 10. Competitive Whitespace — explicit saturation/gap analysis

Before proposing “we should do this too”, scan both supply and unmet need:

- what is already overproduced/commoditized in Russian-speaking business content/products;
- repeated buyer complaints that incumbents still do not resolve;
- new capability that makes previously expensive delivery cheap/fast;
- formats/offers peers repeat so heavily that differentiation is low;
- transferred mechanics rare in the category but proven elsewhere;
- observable demand with friction, not just low competition.

Whitespace remains a hypothesis until demand/fit is tested.

## 11. Cross-Industry Transfer Pass — mandatory serendipity

Broad Radar cycles must deliberately leave the consultant/business bubble. Rotate adjacent industries such as:

`SaaS / beauty / fitness / gaming / hospitality / fintech / e-commerce / creator economy / education / fashion / media-entertainment / marketplaces / crowdfunding / consumer apps`.

Ask:

> **Какая работающая механика здесь переносится в DOKRUTI, даже если тема вообще не про бизнес-консалтинг?**

Examples of transfer logic:

- SaaS onboarding → onboarding of a digital product;
- beauty before/after → business-diagnostic proof;
- fitness challenge → bounded business experiment;
- gaming progress loops → progress/retention mechanics;
- crowdfunding/build-in-public → product development narrative;
- hospitality retention/service → customer-success mechanic;
- social commerce → selling-by-content mechanics.

Copy the mechanism only after transfer-fit and originality checks.

## 12. Trend → DOKRUTI Generator

For each top donor, generate **10–30 materially different applications internally** before shortlisting. Apply it against the **current live pain/COMM-ARCH architecture**, not a hardcoded historical list. If seven pain clusters are still canonical, cover them; otherwise resolve the current set first.

Possible application targets:

`content / offer / product / service / site / sales script / channel packaging / lead magnet / internal process / analytics / positioning / partnership`.

Filter the internal pool by:

`customer value / evidence / originality / strategic fit / speed to proof / owner load / cash cost / legal-platform risk / monetization fit / measurability`.

Owner sees only the strongest shortlist and rejected reasoning when it affects a decision.

## 13. Trend → Money Translator

Every strong signal gets a monetization pass, even if the answer is “none”. Check:

`CONTENT / PRODUCT / SERVICE / AFFILIATE / WHITE-LABEL / B2B / LICENSING / MEDIA / INTERNAL EFFICIENCY`.

For viable routes state:

`who pays or saves money / job-to-be-done / asset or offer / evidence / cheapest proof / economic unknowns / conflicts or rights constraints`.

`NO MONETIZATION FIT` is valid. Do not force a product or affiliate angle onto every signal.

## 14. Experiment Portfolio — proactive 1–3 tests/week

When evidence supports it, Radar should proactively assemble **1–3 high-information tests per week** rather than wait for Svetlana to invent experiments. Prefer reversible, cheap, measurable tests with low owner load.

Experiment brief:

`signal+donor → hypothesis → exact asset/change → baseline → primary metric → guardrail metric → cost/time → success threshold or comparison rule → kill rule → learning destination`.

Owner-gate rules from the main Skill remain unchanged: material public/commercial/legal spend or irreversible action is not launched silently.

## 15. Learning Loop — DOKRUTI-specific evidence

After every test, record:

`mechanic / audience / channel / context / result / metric / likely cause / limitations / repeat? / ADOPT-ADAPT-REJECT / destination`.

One foreign example or one DOKRUTI success does not become a permanent Skill rule. Stable promotion follows `learning-promotion-loop.md`: evidence → repeatability → destination → regression. Dynamic learnings live in the appropriate playbook/channel/content/product object.

## 16. Owner-facing Intelligence Brief

After broad scouting the owner receives a compact decision package, not research theatre:

- **3–7 strongest signals**;
- for each: `donor + evidence + velocity + RU gap + transferable mechanic + DOKRUTI move + money route + risk/unknown`;
- **1–3 proposed tests** with cost/metric/kill rule;
- only true owner gates.

The preferred operating posture is:

> Сегодня я бы проверила вот это. Вот донор и доказательство. Вот механика. Вот почему есть/нет окно раньше русскоязычного рынка. Вот оригинальная версия DOKRUTI. Вот самый дешёвый тест и критерий успеха. От Светланы нужен только реальный owner gate, если он существует.

## 17. Failure conditions

The intelligence cycle fails when any of the following occurs:

- broad Radar is built from a tiny source sample without declaring the coverage gap;
- “global” means one region;
- a generic topic is called a donor without a concrete asset/product/offer/model/mechanic;
- a trend has no current time/velocity evidence;
- `RU GAP` is asserted without an explicit Russian-language scan;
- cross-industry transfer is skipped in a broad scouting cycle;
- strong donor is not translated into an original DOKRUTI test;
- monetization is forced without buyer/economic logic;
- owner receives a raw brainstorm instead of a filtered shortlist;
- a new parallel Radar/Signals/Ideas source of truth is created when an existing canonical object can hold the state;
- learning is promoted to permanent Skill from one anecdote or one test.
