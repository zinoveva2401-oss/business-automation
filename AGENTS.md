# Инструкции для AI-агентов

`AGENTS.md` — единый модельно-нейтральный контракт репозитория проекта `Докрути`.
Модельные адаптеры дополняют, но не переопределяют его.

## Приоритет источников

При противоречии используйте порядок:

1. Последнее прямое решение Светланы по текущему вопросу.
2. Фактическое текущее состояние Google Sheet `Бизнес-система`: прежде всего `00_ШТАБ`, релевантные строки `02_РАБОТА`, последние применимые решения `06_РЕШЕНИЯ`.
3. Актуальный source of truth конкретной задачи / сайта / продукта / материала.
4. Действующий профильный Skill.
5. Актуальный профильный документ Google Drive.
6. Project-копии / GitHub-копии нормативных документов.
7. История чатов и память.

Фактическая среда всегда проверяется для изменяемых объектов: код, ветка, deploy, сайт, сервис, API, тариф, законодательство.

## Минимальное чтение

Не сканируйте весь репозиторий автоматически.

1. Начните с `docs/ai/PROJECT_MAP.md`.
2. Если существует `docs/ai/handoffs/ACTIVE_HANDOFF.md`, прочитайте его до повторного исследования.
3. Для бизнес-контекста используйте `docs/project-knowledge/00-index.md` и только релевантный профильный документ.
4. Для сайта сначала определите текущую ветку/HEAD и фактический активный site-task; не используйте устаревшие удалённые site-документы по памяти.
5. Сверьте инструменты с `docs/ai/AI_CAPABILITIES.md`.

## Рабочий цикл

**UNDERSTAND → READ MINIMUM → CHECK ENVIRONMENT → ACT → VERIFY → WRITE BACK / HANDOFF**

- `DONE ≠ VERIFIED`.
- Не повторяйте уже зафиксированное исследование без нового факта.
- Не расширяйте scope молча.
- Не переписывайте большие файлы ради локальной правки.
- Не перезаписывайте чужой незавершённый diff.
- Не устанавливайте Skill/plugin/MCP/библиотеку без разрешения владельца.
- После двух повторяющихся неудачных попыток по одной причине остановите цикл, определите причину и смените маршрут.

## Большая задача

Для большой работы фиксируйте:
`MAIN`, `STAGES`, `CURRENT STAGE`, `SOURCE OF TRUTH`, `ACCEPTANCE`, `OWNER DECISION REQUIRED`, `TASK BUDGET`, `NEXT ACTION`, `RETURN TO`.

Одновременно по умолчанию один `MAIN`; допускаются до двух коротких независимых `SIDE`.

## Границы ролей

Технический исполнитель не переосмысливает уже утверждённую бренд-, продуктовую, маркетинговую, редакционную или художественную стратегию.
При реальном противоречии сообщите `BLOCKER` и укажите конфликтующие источники.

Профильный исполнитель обязан сам подключать применимые проверки: техника, UX, SEO, безопасность, legal/data, performance, accessibility и другие — по смыслу задачи.

## Git

- До изменений: branch, HEAD, `git status`, `git diff`.
- Не откатывать remote по локальной копии без доказанного diff.
- Коммитить только проверенную связанную работу.
- При передаче фиксировать branch, last known good SHA, проверки и одно точное `NEXT ACTION`.

## Отчёт

После работы перечислите: изменённые файлы, проверки, что VERIFIED, что NOT VERIFIED, риски/блокеры и следующий точный шаг.
