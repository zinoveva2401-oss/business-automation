# TASK_02_ASTRO_FOUNDATION

Статус: Готово к выполнению Qwen Coder  
Тип задачи: СОЗДАНИЕ ТЕХНИЧЕСКОГО ФУНДАМЕНТА  
Рабочая ветка: `site-build-v1`  
Главная ветка `main`: НЕ ИЗМЕНЯТЬ

## Цель

Создать минимальный технический фундамент нового сайта проекта «Розница в цифрах» на Astro, без разработки всей главной страницы и без самовольного визуального дизайна.

## Перед началом

1. Убедись, что существует ветка `site-build-v1`.
2. Переключись на `site-build-v1`.
3. Прочитай `QWEN.md`.
4. Прочитай `docs/site/SITE_SOURCE_OF_TRUTH_v1.1.md`.
5. Не изменяй `main`.
6. Не удаляй и не перемещай существующие `/products/`, `/paid-products/`, `/docs/project-knowledge/`, `README.md`, `AGENTS.md` и другие старые материалы.

## Что нужно создать на этом этапе

### 1. Инициализировать Astro в корне репозитория

Использовать минимальный официальный Astro-проект без сторонней темы и без готового дизайн-шаблона.

Не использовать React, Vue, Svelte, Tailwind, UI-kit или другую интеграцию без отдельной необходимости и разрешения.

### 2. Создать только базовую файловую структуру

Минимально подготовить:

- `src/pages/index.astro`
- `src/pages/articles/index.astro`
- `src/pages/tools/index.astro`
- `src/pages/services/index.astro`
- `src/pages/about.astro`
- `src/pages/contacts.astro`
- `src/layouts/BaseLayout.astro`
- `src/styles/global.css`
- `public/`

Если Astro создаёт дополнительные обязательные системные файлы — сохранить их.

### 3. Создать дизайн-токены в CSS

Зафиксировать переменные минимум для утверждённых цветов:

- `#17130F`
- `#262626`
- `#173B67`
- `#F4F5F6`
- `#FFFFFF`
- `#D8DDE3`
- `#D9562F`
- `#2F80ED`
- `#E7A6B5`

Также подготовить базовые переменные для:
- максимальной ширины контента;
- горизонтальных отступов;
- радиусов;
- вертикального ритма;
- типографической шкалы.

На этом этапе не придумывать сложные компоненты и декоративные эффекты.

### 4. Подготовить BaseLayout

Только техническая база:
- `<html lang="ru">`;
- `<head>`;
- charset;
- viewport;
- title/description как props с безопасными значениями по умолчанию;
- подключение глобальных стилей;
- основной `<slot />`.

Не разрабатывать полноценный header/footer на этом этапе.

### 5. Подготовить страницы-заглушки

Каждая базовая страница должна:
- собираться без ошибок;
- использовать `BaseLayout`;
- иметь один H1;
- содержать только короткую техническую подпись о назначении страницы.

Не переносить в них старый контент.
Не создавать финальные тексты.
Не создавать карточки статей, продуктов или услуг.

### 6. Контентная архитектура

Подготовить техническую основу для Astro Content Collections либо актуального официального механизма контента Astro, если он требуется текущей версии Astro.

Создать схемы/коллекции только для:
- `articles`;
- `tools`.

Минимальные поля:

#### articles
- `title`
- `description`
- `publishedAt`
- `category`
- `draft`

#### tools
- `title`
- `description`
- `price`
- `status`

Не создавать вымышленные статьи и продукты. Допускаются только технические placeholder-файлы, если они необходимы для проверки сборки; такие файлы должны быть явно помечены как draft/test и не предназначаться для публикации.

## Что НЕ делать

На этом этапе запрещено:
- собирать финальный hero;
- копировать визуальный прототип главной;
- создавать весь дизайн главной;
- добавлять motion;
- добавлять Мини-Светлану;
- добавлять реальные или вымышленные статьи;
- добавлять карточки услуг;
- интегрировать HTML-продукт;
- настраивать GitHub Pages deployment;
- добавлять аналитику;
- добавлять форму обратной связи;
- менять README/AGENTS;
- удалять старые файлы;
- менять `main`.

## Проверки

После создания обязательно выполнить фактически:

1. установить зависимости штатным способом;
2. проверить версию Node.js и зафиксировать её в отчёте;
3. выполнить `npm run build`;
4. если предусмотрено стандартным проектом — выполнить доступную проверку типов/линта, но не подключать новый линтер только ради проверки;
5. проверить `git status`;
6. перечислить все новые и изменённые файлы;
7. убедиться, что старые каталоги продуктов и документов не изменены.
