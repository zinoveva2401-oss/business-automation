# SITE_SOURCE_OF_TRUTH_v1.1

Статус: Утверждённая рабочая основа для проектирования  
Проект: «Розница в цифрах»  
Назначение: источник истины для нового публичного сайта

## 1. Позиционирование

«Розница в цифрах» — экспертный проект Светланы Тарасовой о системном управлении малым и средним непродовольственным ритейлом.

Основная идея: **разбирать хаос розничного бизнеса и превращать его в понятную систему: показатели, продажи, товар, покупатель, персонал, управление, маркетинг и прикладные ИИ-инструменты.**

Не использовать инфобизнесовый стиль, громкие обещания, гарантии роста, образ несуществующего агентства и чрезмерную самопрезентацию.

Допустимо использовать формулировки «разберём», «посмотрим», если они описывают совместный путь с читателем и не создают ложного впечатления о большой команде.

## 2. Аудитория

Малый и средний непродовольственный ритейл: одежда, обувь, аксессуары, домашний текстиль, посуда, товары для дома, мебель, строительные и хозяйственные товары, отдельные магазины и локальные сети.

Основные пользователи: собственники, директора, управляющие.

## 3. Цели сайта

1. Привлечение холодной аудитории через статьи и поиск.
2. Накопление базы знаний.
3. Продажа цифровых инструментов.
4. Представление индивидуальных услуг.
5. Показ экспертности Светланы через качество материалов и решений.
6. Единая точка перехода из VK, Дзена, VC.ru, Teletype и других внешних площадок.
7. Контакты и ссылки на подтверждённые публичные каналы.

## 4. Что сайт НЕ делает

Сайт не является личным кабинетом, SaaS, системой директора, внутренней аналитической панелью компании или интеграцией с 1С. Будущие SaaS/корпоративные продукты проектируются отдельно.

## 10. Контент

Основной стартовый формат — статьи.

Первый реальный материал планируется по теме: **пятиминутка директора магазина: что обсуждать с командой и как проводить её правильно.**

Статья должна отвечать на поисковый вопрос, показывать практический опыт, давать конкретную пользу и логично вести к следующему материалу, инструменту или услуге.

## 11. Визуальный референс

Утверждён визуальный прототип главной страницы v2.

Обязательные свойства:
- тёмный редакционный hero;
- реальная сцена магазина;
- светлая аналитическая основная часть;
- крупная редакционная типографика;
- тёмно-синие аналитические блоки;
- оранжевые акценты;
- голубые аналитические акценты;
- рукописные пометки;
- чистая сетка;
- визуальное сочетание редакционного материала и рабочего инструмента.

Не требуется точное копирование текста и временных цифр прототипа. Дизайн, композиционный характер и визуальная система являются утверждёнными.

## 12. Motion

Motion не входит в обязательный первый релиз. Первый экран должен быть сильным без анимации.

В будущем допускается лёгкое смысловое движение: вход покупателя, маршрут, след, движение по торговому залу. Не добавлять движение ради декоративного эффекта.

## 13. Мини-Светлана

Не используется как постоянный элемент интерфейса сайта. Допускается в отдельных редакционных историях, статьях и иллюстрациях.

## 14. Технический стек

Старт:

Принцип: **минимальная достаточная сложность**.

Без базы данных, CMS, сервера и API, пока они не решают подтверждённую задачу.

## 15. Механизм добавления статьи

Новая статья = новый контентный файл. Шаблон статьи не переделывается. Каталог статей обновляется автоматически из контента.

## 16. Механизм добавления продукта

Новый продукт = новый контентный файл/запись. Шаблон продукта не переделывается. Каталог инструментов обновляется автоматически.

## 17. SEO

Для каждой страницы: URL, title, description, H1, H2/H3, canonical, Open Graph, alt, внутренняя перелинковка, breadcrumbs, schema.org, mobile, performance.

Обязательно: `robots.txt`, `sitemap.xml`, `404`, favicon. RSS для статей — если внедряется без лишней сложности.

## 18. n8n

Не использовать для первого ручного релиза. Сначала ручной сценарий публикации должен стабильно работать. Автоматизация — только после этого.

## 19. Контакты

Нужна отдельная страница контактов и быстрый контактный блок на главной.

Добавляются только подтверждённые Telegram, MAX, WhatsApp, e-mail и другие публичные каналы. Никаких выдуманных контактов.

## 20. Юридические страницы

До коммерческого запуска определить и подготовить по фактической схеме:
- политику обработки персональных данных;
- согласие на обработку данных, если собираются заявки;
- сведения о продавце/исполнителе;
- условия приобретения цифрового продукта / оферту при необходимости;
- правила возврата/отказа согласно реальной схеме продажи.

## 21. Главный принцип разработки

Сначала три эталона:
1. главная;
2. статья;
3. продукт.

Только после утверждения этих трёх типов масштабировать сайт.
