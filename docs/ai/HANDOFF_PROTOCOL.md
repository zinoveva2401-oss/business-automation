# HANDOFF_PROTOCOL

Статус: Действующий протокол передачи задач
Проект: «Розница в цифрах»
Назначение: компактная передача незавершённой задачи между агентами

## 1. Назначение

Компактный протокол передачи незавершённой задачи между агентами.
Позволяет следующему агенту продолжить работу без полного повторного исследования.

## 2. Когда создавать handoff

- Лимит токенов или контекста.
- Ошибка или блокировка.
- Плановая смена исполнителя.
- Передача задачи другому агенту.
- Передача части производства другому исполнителю.

## 3. Где хранить

- Активный handoff: `docs/ai/handoffs/ACTIVE_HANDOFF.md`
- Один активный handoff на задачу.
- После завершения — переместить в `docs/ai/handoffs/archive/`.

## 4. Формат handoff-файла

```markdown
# HANDOFF: [задача]

- TASK_ID: [уникальный идентификатор]
- SOURCE_OF_DECISION: [кто и когда утвердил задачу]
- CREATED_BY: [агент / модель и дата-время]
- WORKING_BRANCH: [текущая ветка Git]
- LAST_KNOWN_GOOD_COMMIT: [SHA последнего рабочего commit]

## ОГРАНИЧЕНИЯ / ЗАБЛОКИРОВАНО

- [список заблокированных файлов/решений]

## FILES_CHANGED

- [путь 1]
- [путь 2]

## ВЫПОЛНЕНО

- [список выполненных действий]

## ПРОВЕРЕНО

- [список проверок и их результат]

## ОСТАВШЕЕСЯ

- [список оставшихся действий]

## БЛОКИРОВЩИКИ

- [описание препятствия, если есть]

## РЕШЕНИЯ ПО ВОСХОДЯЩЕМУ ПОТОКУ

- [решения вышестоящих ролей, которые нельзя переосмысливать]

## NEXT EXACT ACTION

- [одно конкретное действие с указанием файла/команды]
```

## 5. Приём handoff

Принимающий агент:

1. Читает `ACTIVE_HANDOFF.md` первым.
2. Не повторяет исследование, если handoff содержит решение.
3. Проверяет `working_branch` и `last_known_good_commit`.
4. Продолжает с `NEXT EXACT ACTION`.
5. После завершения — архивирует handoff.

## 6. Передача между разными агентами

Handoff-файл модельно-нейтрален.
Любой агент (Qwen, Codex, Gemini, DeepSeek) может принять handoff.
Модельно-специфичные детали — в соответствующем адаптере (QWEN.md, CLAUDE.md и т.п.).
